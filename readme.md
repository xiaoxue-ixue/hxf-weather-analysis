



# 基于Streamlit+AI Agent的云南省天气数据可视化分析应用研究

## 1. 项目概述

### 1.1 项目名称
基于Streamlit+AI Agent的云南省天气数据可视化分析应用研究

### 1.2 项目定位
本项目是一个基于 Python 的天气数据采集、处理、分析与预测的综合数据应用系统。通过网络爬虫技术获取云南省各城市历史天气数据，经过数据清洗和特征工程处理后，提供直观的数据可视化分析和基于机器学习的气温预测功能。

### 1.3 项目目标
- 自动采集云南省各城市2015年以来的天气数据
- 提供完整的数据清洗和预处理流程
- 通过可视化图表展示天气数据特征和趋势
- 基于机器学习模型实现气温预测功能
- 提供友好的 Web 交互界面

## 3. 功能模块

### 3.1 数据采集模块 (`user/data_collection.py`)

**功能说明：**
- 从天气后报网站（https://www.tianqihoubao.com）爬取云南省各城市天气数据
- 支持增量采集（跳过已存在的数据）
- 自动过滤2015年之前的历史数据

**核心功能：**

| 功能点 | 说明 |
| :--- | :--- |
| 城市链接解析 | 解析云南省下辖城市列表 |
| 月份链接解析 | 解析每个城市的历史月份数据链接 |
| 天气数据解析 | 解析每日天气信息（日期、天气类型、气温、风向风力） |
| 去重机制 | 基于城市+年月的重复数据检测 |
| 数据存储 | 自动保存到 SQLite 数据库 |

### 3.2 数据处理模块 (`user/data_processing.py`)

**功能说明：**
- 对原始天气数据进行全面清洗和预处理
- 输出高质量的结构化数据供后续分析使用

**处理流程：**

| 步骤 | 处理内容 | 说明 |
| :--- | :--- | :--- |
| 1 | 数据基本信息检查 | 查看数据结构、字段类型、唯一值统计 |
| 2 | 重复值处理 | 检测并删除重复记录 |
| 3 | 日期特征处理 | 提取年、月、日、周、年内天数、季节等特征 |
| 4 | 风力等级简化 | 将原始风力等级映射为弱风/中风/强风/大风 |
| 5 | 缺失值处理 | 使用向前填充法处理气温缺失值 |
| 6 | 温度格式标准化 | 去除温度单位，转换为整数类型 |
| 7 | 数据类型转换 | 统一字段数据类型 |

## 数据处理模块问题分析与处理作用说明

### 1. 数据基本信息检查

**处理前问题：**
- 不清楚数据的整体结构（行数、列数）
- 不了解各字段的数据类型是否正确
- 无法判断离散特征的唯一值数量和分布
- 缺乏对数据质量的整体认知

**处理作用：**
- 通过 `df.info()` 输出数据结构、字段类型、非空值数量
- 统计离散特征（城市、天气类型、风向、风力）的唯一值，了解数据多样性
- 为后续处理步骤提供决策依据

---

### 2. 重复值处理

**处理前问题：**
- 爬虫采集过程中可能产生重复数据（如网络重试、重复爬取）
- 重复数据会导致分析结果失真（统计量偏高）
- 增加存储空间占用和计算负担

**处理作用：**
- 使用 `duplicated()` 检测重复记录
- 通过 `drop_duplicates()` 删除重复数据
- 展示处理前后的数据量对比，直观展示去重效果

---

### 3. 日期特征处理

**处理前问题：**
- 日期存储为字符串格式（如 "2025年01月01日"），无法进行时间相关计算
- 缺乏年、月、日、周等时间维度的特征
- 无法按季节进行分析

**处理作用：**
- 将日期字符串转换为 `datetime` 类型
- 提取年、月、日、周数、年内天数等时间特征
- 新增季节特征（春/夏/秋/冬），支持季节性分析
- 为后续时间序列分析和模型训练提供基础特征

---

### 4. 天气类型简化

**处理前问题：**
- 天气类型种类过多（如毛毛雨、细雨、小雨、阵雨等）
- 相似天气类型分散，不利于统计分析
- 过多类别会降低模型训练效率和效果

**处理作用：**
- 将多种天气类型归类为6大类：晴天、多云、阴天、雨天、雪天、雾天、其他
- 使用集合进行快速匹配，提高处理效率
- 减少特征维度，便于后续可视化和建模

---

### 5. 风力等级简化

**处理前问题：**
- 风力等级格式不统一（如 "1-2级"、"微风"、"3-4级级"、"3～4级"）
- 存在格式错误（如"3-4级级"多了一个"级"）
- 中文描述和数字描述混用，难以直接分析

**处理作用：**
- 统一映射为4个等级：弱风、中风、强风、大风
- 建立标准化的映射字典，处理各种格式变体
- 消除格式错误，提高数据一致性

---

### 6. 缺失值处理

**处理前问题：**
- 气温数据可能存在缺失（爬虫解析失败或数据本身缺失）
- 缺失值会导致统计分析结果不准确
- 机器学习模型无法处理含缺失值的数据

**处理作用：**
- 使用向前填充（ffill）方法填充缺失值（基于时间连续性，相邻日期气温差异小）
- 展示缺失值处理前后的对比
- 保证数据完整性，支持后续分析和建模

---

### 7. 温度格式标准化

**处理前问题：**
- 温度包含单位符号（如 "25℃"），存储为字符串类型
- 无法直接进行数值计算和统计分析
- 缺少平均气温特征

**处理作用：**
- 去除温度值中的"℃"符号
- 将温度转换为整数类型
- 计算平均气温（最高温+最低温/2），新增特征列
- 为数据分析和模型训练提供数值型温度特征

---

### 8. 数据类型转换

**处理前问题：**
- 类别型字段可能存储为 object 类型
- 周数（week）可能为浮点数类型
- 不一致的数据类型会影响分析效率和模型性能

**处理作用：**
- 将类别字段统一转换为 string 类型
- 将周数字段转换为整数类型
- 优化内存占用和计算效率
- 确保数据类型符合后续分析和建模要求

---

## 数据处理流程总结

| 处理步骤 | 解决的问题 | 处理后效果 |
|---------|-----------|-----------|
| 数据检查 | 数据结构不清晰 | 明确数据规模和特征分布 |
| 重复值处理 | 重复数据影响分析结果 | 数据唯一性得到保证 |
| 日期特征处理 | 日期为字符串格式 | 支持时间序列分析 |
| 天气类型简化 | 天气类型过多过细 | 类别统一，便于分析 |
| 风力等级简化 | 风力格式不统一 | 标准化等级划分 |
| 缺失值处理 | 部分数据缺失 | 数据完整可用 |
| 温度格式标准化 | 温度带单位符号 | 可进行数值计算 |
| 数据类型转换 | 类型不一致 | 优化内存和计算效率 |

经过以上处理，原始数据从**杂乱无章的原始爬虫数据**转变为**结构清晰、格式规范、质量可靠**的分析-ready数据，为后续的可视化分析和机器学习建模奠定坚实基础。

### 3.3 数据可视化分析模块 (`user/data_visualization_analysis.py`)

### 3.4 气温预测模块 (`user/temperature_forecast.py`)

**功能说明：**
- 基于随机森林回归算法构建气温预测模型
- 支持最高气温和最低气温的预测

**核心流程：**

| 阶段 | 功能 | 说明 |
| :--- | :--- | :--- |
| 特征工程 | 特征选择与编码 | 选择7个特征，对城市进行目标编码 |
| 数据集划分 | 训练集/测试集分割 | 80%训练集，20%测试集 |
| 模型训练 | 随机森林回归 | 分别训练最高温和最低温模型 |
| 模型评估 | 多指标评估 | MAE、MSE、RMSE、R² |
| 模型应用 | 实时预测 | 输入城市和日期，返回预测结果 |

**模型评估指标：**
- **MAE（平均绝对误差）**：衡量预测值与真实值的平均偏差
- **MSE（均方误差）**：对较大误差给予更大权重
- **RMSE（均方根误差）**：与原始数据量纲一致，直观反映预测偏差
- **R²（决定系数）**：衡量模型对数据的拟合程度（0~1）

## 4. 数据流程

### 4.1 数据采集流程
```
天气后报网站 → 城市列表解析 → 月份链接解析 → 每日天气解析 → 去重检查 → SQLite存储
```

### 4.2 数据处理流程
```
原始数据表 → 重复值处理 → 日期特征提取 → 风力等级简化 → 缺失值处理 → 温度标准化 → 类型转换 → 清洗后数据表
```

### 4.3 模型训练流程
```
清洗后数据 → 特征选择 → 特征编码 → 数据集划分 → 模型训练 → 模型评估 → 模型保存
```

### 4.4 预测应用流程
```
用户输入（城市+日期）→ 特征构建 → 模型加载 → 气温预测 → 结果展示
```

## 8. 使用说明

1. **数据采集**：首次采集可能耗时较长，请耐心等待；后续采集会自动跳过已存在的数据

3. **依赖环境**：确保已激活虚拟环境运行应用
4. **数据库**：SQLite 数据库文件位于 `db/weather.db`，请勿手动修改
5. **模型文件**：训练好的模型保存在 `model/` 目录下
6. **AI 功能**：需要配置 Dify API Key 才能使用智能问答和图表解读功能
7. **网络依赖**：AI 功能需要联网调用 Dify API
